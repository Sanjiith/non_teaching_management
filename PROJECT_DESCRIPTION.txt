The BIT Non-Teaching Staff Portal is a full-stack web application built for Bannari Amman Institute of Technology (BIT Sathy) to digitally manage the administrative workflows of non-teaching staff. The backend runs on Node.js with Express and MongoDB via Mongoose, and the frontend is a React 18 application bundled with Vite, styled using Tailwind CSS, and communicating with the server through Axios. The system defines three user roles: Admin, HOD (Head of Department), and Staff (also called Non-Teaching Staff internally), each with a separate protected dashboard and set of pages. Authentication is JWT-based; users log in with their employee ID or email and password, the server verifies credentials using bcrypt password comparison, issues a signed JWT, and the client stores it in localStorage to restore the session on reload. Every protected API route runs through the auth middleware (which validates the token) and the role middleware (which checks whether the caller's role is permitted), and a department-level isolation guard additionally prevents HODs and Staff from accessing data belonging to other departments. Input on all API routes is validated through dedicated validator modules covering auth, user, department, attendance, leave, shift, schedule, and payroll requests. The Admin has full system access: they can create, update, and deactivate department records (each with a name, unique code, and an assigned HOD reference); create and manage staff accounts (storing name, employee ID, designation, phone, joining date, basic salary, and profile image); define shift configurations (name, start time, end time, working hours, optional department link); assign shifts to staff by creating daily schedule entries; mark and bulk-manage attendance records across all departments; review and approve or reject leave applications from any staff member; generate and manage payroll records for all staff; and access system-wide reports. The HOD role is scoped strictly to their own department: they can view and manage attendance for their staff, approve or reject leave requests from their department, assign shifts to their department staff through the schedule module, and view payroll records within their department. Staff members can view their own attendance history, submit leave applications specifying a type (Casual Leave, Medical Leave, Earned Leave, Maternity Leave, Paternity Leave, or Other), a date range, optional start and end times, and a reason, then track the application through Pending, Approved, Rejected, or Cancelled states, view their assigned daily schedule, and view their own payroll slips. The leave module tracks balances per staff member with 12 days each allocated for Casual, Medical, and Earned leave; when a leave application is submitted, the requested days are reserved against the balance, and on approval they are marked as used, while on rejection or cancellation the reservation is released. The server also enforces overlap detection to prevent a staff member from submitting two leave requests with overlapping date ranges, and supports half-day leaves (0.5 days) detected when the leave spans a single day with a midday start or end time. The payroll module performs all salary calculations server-side: the applicable salary is capped at a maximum of forty thousand rupees regardless of the staff member's actual basic salary, then divided by the total working days in the month (calendar days excluding Sundays and any declared holidays) to derive a daily salary rate; unauthorized absent days are multiplied by this daily rate to compute the absence deduction; approved leave days are not deducted; allowances (HRA, DA, TA, medical, other) and deductions (PF, PT, TDS, loan repayment, other) fields exist in the model for extensibility but default to zero; the gross salary is the applicable salary plus total allowances, and the net salary is the gross salary minus the absence deduction and total deductions. Each payroll record progresses through Draft, Processed, and Paid statuses and is generated and managed exclusively by the Admin. The notification system creates in-app database notifications linked to individual users whenever key events occur, such as when a leave application is submitted, approved, rejected, or cancelled, or when a shift schedule is assigned. The report module aggregates real database records to provide attendance summaries (per staff, per department, per month), leave summaries, and payroll overviews, with the Admin seeing system-wide data, the HOD seeing department-scoped data, and Staff seeing only their own records. The server also includes a database seed script that creates default test accounts for all three roles (Admin, HOD, and Staff) with known credentials, an earned leave migration script to backfill leave balances for existing users, and seven test files covering authentication and role-based access control, attendance and leave interaction logic, shift and schedule assignment, and payroll computation, written using a combination of unit and integration test patterns.
